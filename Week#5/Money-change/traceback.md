Щоб не просто дізнатися **мінімальну кількість** монет, а й побачити **самі монети**, нам потрібно "запам'ятовувати дорогу". У динамічному програмуванні це називається **відстеженням шляху (backtracking)**.

Ми додамо ще один масив `coinUsed`, куди для кожної суми будемо записувати останню монету, яка допомогла досягти мінімуму.

### Як працює технологія відстеження:

1. **Заповнення таблиці**: Коли ми знаходимо кращий варіант для суми `m` (використовуючи монету `coin`), ми не лише оновлюємо кількість у `minNumCoins[m]`, а й записуємо в `coinUsed[m] = coin`.
2. **Реконструкція шляху**: Починаємо з повної суми `money`. Дивимось у `coinUsed[money]`, щоб дізнатися, яка була остання монета. Віднімаємо її номінал від суми і повторюємо процес, поки не дійдемо до нуля.

---

### Код на Python з поясненнями

```python
def PDChange_with_path(money, coins):
    # minNumCoins[m] зберігає мін. кількість монет для суми m
    minNumCoins = [money + 1] * (money + 1)
    # coinUsed[m] зберігає останню монету, використану для суми m
    coinUsed = [0] * (money + 1)
    
    minNumCoins[0] = 0
    
    # 1. Заповнюємо таблицю (Динамічне програмування)
    for m in range(1, money + 1):
        for coin in coins:
            if coin <= m:
                # Якщо використання цієї монети дає меншу кількість, ніж ми вже маємо
                if minNumCoins[m - coin] + 1 < minNumCoins[m]:
                    minNumCoins[m] = minNumCoins[m - coin] + 1
                    # Запам'ятовуємо, яку саме монету використали
                    coinUsed[m] = coin
    
    # 2. Відстежуємо шлях (Реконструкція списку монет)
    res_coins = []
    current_money = money
    
    while current_money > 0:
        # Дістаємо монету, яку ми записали для поточної суми
        last_coin = coinUsed[current_money]
        res_coins.append(last_coin)
        # Зменшуємо залишок суми
        current_money -= last_coin
        
    return minNumCoins[money], res_coins

# Введення даних
try:
    money_input = int(input("Введіть суму: "))
    available_coins = tuple(map(int, input("Введіть номінали монет: ").split()))
    
    count, path = PDChange_with_path(money_input, available_coins)
    
    print(f"Мінімальна кількість монет: {count}")
    print(f"Перелік монет: {path}")
except ValueError:
    print("Будь ласка, введіть ціле число.")

```

---

### Що змінилося в логіці?

* **Масив `coinUsed**`: Це ваш "журнал", де записано кожне правильне рішення на кожному кроці. Без нього комп'ютер знає *скільки* монет треба, але миттєво "забуває", *які* саме це були монети після завершення циклу.
* **Цикл `while**`: Це зворотний хід. Уявіть, що ви йшли лісом і кидали крихти хліба (записували монети в масив). Тепер ви просто йдете по цих крихтах назад від фінішу до старту.

**Приклад роботи для суми 6:**

1. Алгоритм знайде, що для 6 найкраще взяти монету **3** (залишиться 3).
2. Для залишку 3 найкраще взяти монету **3** (залишиться 0).
3. Результат: `[3, 3]`. (Хоча жадібний алгоритм міг би взяти `4, 1, 1`, що гірше).


### Чи можна обійтися без другого масиву?

Так, можна обійтися **без другого масиву** `coinUsed`, якщо ви готові трохи пожертвувати часом на етапі відновлення шляху.

### Технологія "Відновлення на основі різниці"

Замість того, щоб записувати, яку монету ми використали, ми можемо після заповнення основної таблиці `minNumCoins` "відмотати" результат назад, перевіряючи кожну доступну монету.

**Логіка така:**
Якщо для суми $m$ мінімальна кількість монет дорівнює $K$, то існує така монета $c$ із нашого набору, що для суми $(m - c)$ мінімальна кількість монет дорівнювала $(K - 1)$.

---

### Код без масиву `coinUsed`

```python
def PDChange_no_extra_space(money, coins):
    # Основна таблиця динамічного програмування
    minNumCoins = [money + 1] * (money + 1)
    minNumCoins[0] = 0
    
    # 1. Заповнюємо таблицю як зазвичай
    for m in range(1, money + 1):
        for coin in coins:
            if coin <= m:
                if minNumCoins[m - coin] + 1 < minNumCoins[m]:
                    minNumCoins[m] = minNumCoins[m - coin] + 1
    
    # 2. Відновлюємо шлях, аналізуючи значення в minNumCoins
    res_coins = []
    current_money = money
    
    while current_money > 0:
        for coin in coins:
            # Перевіряємо, чи ця монета могла бути частиною оптимального шляху
            if coin <= current_money and minNumCoins[current_money - coin] == minNumCoins[current_money] - 1:
                res_coins.append(coin)
                current_money -= coin
                break # Знайшли монету, переходимо до наступного залишку
                
    return minNumCoins[money], res_coins

money = 6
coins = [1, 3, 4]
print(PDChange_no_extra_space(money, coins))

```

### Плюси та мінуси цього підходу:

* **Плюс (Пам'ять):** Ми економимо $O(money)$ пам'яті, бо не створюємо список `coinUsed`. Нам потрібен лише масив `minNumCoins`.
* **Мінус (Час):** На етапі відновлення шляху для кожної монети в результаті ми знову перебираємо список доступних номіналів `coins`. Якщо кількість типів монет дуже велика, це буде повільніше.

**Чому зовсім без масивів не можна?**
Динамічне програмування за своєю суттю — це обмін пам'яті на час. Щоб знайти оптимальний розмін для великої суми, нам обов'язково треба знати відповіді для менших сум. Без збереження цих значень (масиву) задача перетворюється на повний перебір (рекурсію), що працюватиме вічність на великих числах.
